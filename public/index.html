Change-safety gate for AI-generated code

Every AI-written change reviewed before it ships.

    Built for the ways AI agents break things

    Linters look for bad code. Iron Mountain also looks at what a change takes away.

    Removed and stubbed security

    A deleted requireAuth that never came back, or isAdmin() that now just returns true.

    Hallucinated packages

    New dependencies are checked live on npm and PyPI. Missing, days-old, typosquatted and known-malicious names are flagged.

    Prompt injection and hidden text

    Instructions aimed at AI reviewers, and invisible bidi and zero-width characters (Trojan Source).

    Agent config tampering

    Edits to CLAUDE.md, AGENTS.md, .cursorrules, MCP server lists, or settings like bypassPermissions.

    Tests made to pass

    Skipped, focused or deleted tests, and assertions removed on net.

    The classics

    Secrets, SQL and command injection, SSRF, XSS, weak crypto, disabled TLS, risky CI workflows, public cloud resources.

    Runs wherever the code is written

    Claude Code

    A hook scans each file as Claude writes it and sends findings straight back, so they get fixed before Claude moves on.

    ironmountain init --claude

    Any MCP client

    Cursor, Windsurf, VS Code, Codex CLI, Gemini CLI and Claude Desktop can check their own output.

    ironmountain mcp

    Pull requests

    A GitHub Action or App posts a summary, inline comments, a required check and SARIF.

    uses: airostudio/ironmountain

    Terminal and git hooks

    Review the working tree, a branch or staged changes. Exit code 1 means blocked.

    ironmountain review --base main

    The reviewer can't be talked out of a block

    The code under review is untrusted, and so is any model that reads it.

    • The Claude reviewer can add findings, but it can never dismiss critical, secret, supply-chain or AI-integrity findings.
    • Reviewed content is fenced as untrusted data, and the reviewer reports injected instructions instead of following them.
    • Agent tools are read-only and confined to the repository, with no symlink escapes and no .git/ access.
    • Changes written by AI automatically get a stricter gate, and their suppressions need a written reason.
    • PR policy is read from the base branch, so a change can't loosen its own gate.
